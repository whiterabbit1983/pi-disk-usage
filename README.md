# pi-disk-usage

Расширение **Pi Coding Agent 1.5.2+** для Linux: кликабельный индикатор занятого места, отдельный топ-20 файлов/папок для каждого доступного домашнего каталога и рекомендации по очистке. Поддерживается работа на хосте и внутри Docker-контейнера.

## Установка

Из каталога проекта:

```bash
pi install /home/poweruser/work/pi-disk-usage
```

Затем выполните `/reload` в работающем pi или перезапустите его. Исходники остаются в этом каталоге; копировать их в `~/.pi/agent/extensions` не нужно.

Разовый запуск без установки:

```bash
pi -e /home/poweruser/work/pi-disk-usage/src/index.ts
```

Удаление из конфигурации:

```bash
pi remove /home/poweruser/work/pi-disk-usage
```

Для работы не нужны npm-зависимости, кроме библиотек самого pi. Требуются GNU coreutils (`df`, `du`, `timeout`) и `flock` из util-linux. В контейнере занятый объём и рейтинги измеряются GNU `du`. Общий счётчик запускается в отдельном Node.js-процессе (Node.js 22.18+). Команды рекомендаций предполагают наличие соответствующей программы; ничего не устанавливается автоматически.

## Язык интерфейса / Interface language

Язык определяется автоматически по первой непустой переменной окружения: `LC_ALL` → `LC_MESSAGES` → `LANG`. Для русской локали (`ru`, `ru_RU.UTF-8`, `ru-RU` и т. п.) интерфейс, ошибки плагина и рекомендации показываются на русском; для всех остальных, включая `C`, `POSIX` и отсутствие локали, — на английском. Команды, пути и сообщения внешних программ не переводятся. `df`/`du` по-прежнему запускаются с `LC_ALL=C` для стабильного разбора вывода.

The interface language is detected from the first non-empty environment variable: `LC_ALL` → `LC_MESSAGES` → `LANG`. Russian locales use Russian; all other locales (including `C`, `POSIX` or unset variables) use English. This covers the indicator, report, plugin errors and cleanup recommendations. Commands, paths and external program diagnostics are not translated.

Можно явно задать язык при запуске / To override the language when launching Pi:

```bash
LC_ALL=ru_RU.UTF-8 pi  # Русский
LC_ALL=C pi           # English
```

## Индикатор и цвета

Под редактором появляется, например:

```text
Диск: занято 53.2% · 133.1 GB / 250.4 GB  [клик / /disk]
```

**На хосте** раскраска зависит от **процента занятой ёмкости**, а не от абсолютного количества GB:

| Занято | Цвет |
| --- | --- |
| ≤ 70% | Зелёный |
| > 70% и < 80% | Жёлтый |
| 80–90% включительно | Оранжевый |
| > 90% | Красный |

Жёлтый добавлен для диапазона 70–80%, не указанного в исходной схеме. Пороги определяются по точному значению до округления надписи. Цвета фиксированы и не подменяются палитрой темы.

**Индикатор** обновляется сразу при старте Pi, затем каждые **3 минуты на хосте** или **10 минут в контейнере**. Если предыдущее фоновое измерение ещё выполняется, очередной запуск пропускается. При ошибке индикатор сохраняет последнее полученное значение без сообщения о сбое; если успешных измерений ещё не было, показывает `Диск: --` (`Disk: --`).

**Окно отчёта** получает общий счётчик из действительного кэша (либо обновляет просроченный), а размеры `/tmp` и отдельные топ-20 пересчитывает при каждом открытии `/disk` и по клавише `r`. Открытый отчёт показывает снимок данных и не обновляется автоматически по таймеру индикатора. Фоновое обновление индикатора не запускает повторный обход домашних каталогов.

### Несколько процессов Pi: общий кэш

Все процессы одного пользователя в одной среде используют общий кэш счётчика: **3 минуты на хосте**, **10 минут в контейнере** с момента завершения измерения. Запуск новых Pi, открытие `/disk` и `r` не запускают новый `du`/`df`, пока результат действителен.

- Один процесс измеряет; другие ждут под межпроцессной блокировкой ядра Linux (`flock`). Получив блокировку, каждый повторно проверяет кэш, поэтому параллельные запросы не превращаются в последовательные повторные сканирования.
- Пока счётчик обновляется, предыдущий результат, если он есть, помечен как **«предыдущее измерение»**. При сбое индикатор сохраняет предыдущее значение (или `--`, если его нет); подробная ошибка доступна в окне отчёта. Ошибки измерения разделяются на 5 секунд, чтобы несколько Pi не повторяли одновременно заведомо неудачный запуск.
- Ключ включает UID/GID/группы, boot ID, mount/user/PID namespaces, корень файловой системы и режим хост/контейнер. Хост, разные контейнеры и пользователи не смешиваются. Для совместного использования нужны также одинаковые `XDG_RUNTIME_DIR`/`TMPDIR` и доступ к одному каталогу кэша.
- Хранилище: `$XDG_RUNTIME_DIR/pi-disk-usage-<UID>/`, если runtime-каталог приватен и принадлежит пользователю; иначе `<os.tmpdir()>/pi-disk-usage-<UID>/` (обычно `/tmp`). Каталог — `0700`, файлы данных/блокировки — `0600`. Небезопасный каталог или недоступный кэш вызывают ошибку, а не незаметное переключение на независимые сканирования.
- JSON записывается через временный файл и атомарное переименование. Повреждённые/несовместимые записи игнорируются. Lock-файлы намеренно **не удаляются**: это сохраняет один inode для всех ожидающих; сама блокировка освобождается ядром при завершении процесса.
- Общий worker продолжает работу после закрытия отчёта, `/reload` или завершения одного Pi, чтобы не срывать измерение для остальных. Отдельный GNU `timeout` ограничивает всю группу worker/du **140 секундами**, включая ожидание блокировки; сам `du` ограничен 120 секундами. Постоянный сервис не запускается.
- В кэше нет настроек цветов, имён файлов топ-20 или результатов сканирования домашних каталогов. Пороги GB применяются локально каждым Pi. Рейтинги и отдельный размер `/tmp` по-прежнему измеряются только по запросу и не разделяются между процессами.

### Что входит в счётчик

На хосте `df` получает статистику **локальных смонтированных файловых систем**, а не размер домашнего каталога. Поэтому учитываются `/usr`, `/var`, `/opt`, `/tmp` и любые другие каталоги на этих файловых системах, в том числе недоступные для чтения текущему пользователю.

- Отдельные файловые системы `/home`, `/boot`, диски в `/mnt` и т. п. включаются в общую сумму.
- Bind-mount одного устройства не считается повторно.
- Сетевые и несмонтированные диски не учитываются.
- Псевдофайловые системы, `/run`, `/dev/shm` и read-only squashfs-образы исключены.
- Если `/tmp` или `/var/tmp` сами смонтированы как tmpfs/ramfs, они включаются отдельной строкой, даже несмотря на то, что это память, а не физический диск.
- Процент = сумма `used` / сумма `size` × 100. По каждой файловой системе процент также показан отдельно: общая сумма может скрывать заполнение одного небольшого раздела.
- `available` — доступное пользователю место; из-за резерва файловой системы оно может быть меньше `size − used`.
- GB — десятичные гигабайты: 1 GB = 1 000 000 000 байт.

## Docker и другие контейнеры

Контейнер определяется по `/.dockerenv`, `/run/.containerenv`, признакам в cgroup или переменной `container`. Поддерживаются в том числе Docker с cgroup v2 и rootless Podman. Сам по себе `overlay` не считается доказательством контейнера.

- Показывается **только занятый объём**, например `Контейнер /: занято 55.0 GB`. Общая ёмкость, свободное место и проценты не выводятся ни в индикаторе, ни в отчёте.
- Измеряются выделенные блоки **видимых файлов** под `/`, включая подключённые тома, bind-mount и `/tmp`. Служебные деревья `/proc`, `/sys`, `/dev`, `/run` исключаются. Символические ссылки не раскрываются; GNU du учитывает жёсткие ссылки один раз в пределах обхода. Разные представления данных через bind-mount/overlay могут влиять на результат.
- Это **не** размер записываемого слоя или virtual size из `docker ps -s`, не объём backing-диска хоста, не дисковая квота. Образы и скрытые слои других контейнеров не измеряются. Права root, Docker socket и доступ к хостовым путям слоёв не нужны.
- При недостатке прав или изменении файлов данные могут быть занижены: индикатор показывает пометку **«неполные данные»**. При полном сбое/таймауте индикатор сохраняет предыдущее значение или `--`, а окно отчёта показывает ошибку. Сам обход ограничен 120 секундами; общий worker живёт независимо от отдельных окон/Pi (см. общий кэш выше). Сообщения `Permission denied`, `Access denied`, `Operation not permitted` от `du` отбрасываются и не попадают ни в интерфейс, ни в кэш ошибок.
- Для ручной проверки вместо округлённого `du -sh /` рекомендуется GNU-команда (байты, десятичные GB в интерфейсе):

  ```bash
  du --block-size=1 --summarize --no-dereference \
    --exclude=/proc --exclude=/sys --exclude=/dev --exclude=/run -- /
  ```

- Сканируются только домашние каталоги, видимые внутри контейнера. Рекомендации не предполагают наличие sudo, systemd, journald или APT и не предлагают очистку Docker через проброшенный socket.

### Цвета в контейнере и настройка порогов

| Занято | Цвет |
| --- | --- |
| < 50 GB | Зелёный |
| ≥ 50 и < 60 GB | Жёлтый |
| ≥ 60 и < 70 GB | Оранжевый |
| ≥ 70 GB | Красный |

Границы сравниваются до округления. Можно задать три возрастающих неотрицательных числа в GB через переменную окружения **процесса Pi внутри контейнера**:

```bash
PI_DISK_USAGE_CONTAINER_THRESHOLDS_GB=40,55,80 pi
```

Для Docker Compose:

```yaml
environment:
  PI_DISK_USAGE_CONTAINER_THRESHOLDS_GB: "40,55,80"
```

Это начала жёлтого, оранжевого и красного диапазонов. Допускаются дробные значения (например `40.5,55,80`); неверный формат вызывает ошибку измерения с пояснением. Без переменной используются `50,60,70`. **На хосте переменная игнорируется**, процентные пороги не меняются.

В минимальном образе установите инструменты при сборке: `apt-get install coreutils util-linux` (Debian/Ubuntu) или `apk add coreutils util-linux` (Alpine). BusyBox `du` не поддерживает нужный потоковый формат GNU `du`; при несовместимых опциях плагин покажет пояснение. Coreutils не устанавливаются автоматически.

## Открытие отчёта

- **Полноэкранный режим:** щёлкните левой кнопкой по цветной надписи.
- **Любой интерактивный режим:** команда `/disk`.
- В обычном режиме pi клики остаются у терминала. Для кликов запустите `pi --tui-mode fullscreen`.

Управление отчётом:

| Клавиша | Действие |
| --- | --- |
| ↑ / ↓, колесо мыши | Прокрутка |
| PgUp / PgDn | Прокрутка страницами |
| `c` | Перейти к рекомендациям по очистке; повторно — в начало |
| `r` | Обновить статистику и пересканировать |
| Esc / Ctrl+C / `q` / кнопка `[×]` | Закрыть и отменить сканирование |

Настроенные привязки pi для навигации и отмены также учитываются. Отчёт работает без вызова модели и не добавляет список ваших файлов в контекст LLM.

### Топ-20

Рекурсивно сканируются **текущий домашний каталог и все доступные каталоги непосредственно в `/home`**, включая их скрытые и вложенные файлы/папки. Для **каждого доступного домашнего каталога показывается отдельный топ-20** со своим заголовком, полным путём каталога, его размером и нумерацией с 1. Если в каталоге меньше 20 доступных файлов/папок, показываются все. Списки не объединяются и не сокращаются до общего лимита в 20 строк. Сам корень каждого сканируемого домашнего каталога в рейтинг не включается.

- Текущий домашний каталог учитывается и тогда, когда он расположен вне `/home`, например `/root`.
- Совпадающие пути и вложенные корни сканирования не обходятся повторно. Ссылки на каталоги в `/home` не раскрываются.
- Проверяются права чтения и прохода в каталог. Если `/home` недоступен, сканируется только доступный текущий домашний каталог. Закрытые и исчезнувшие каталоги пропускаются молча, в том числе если доступ изменился после начала обхода.
- Для своих файлов выводится `~/…`, для остальных — полный путь, например `/home/other-user/file`. Рекомендации по пользовательским кэшам относятся только к вашему домашнему каталогу, не к данным других пользователей.
- Общий размер — сумма измеренных доступных домашних каталогов, а не размер всех файловых систем. Жёсткие ссылки между разными домашними каталогами могут учитываться в нескольких суммах.

- `DIR` — каталог, `FILE` — файл, `LINK` — символическая ссылка.
- Размер — реально выделенные блоки (`du`), а не логический размер sparse-файла.
- Размер папки включает вложенные файлы/папки. Поэтому **строки рейтинга нельзя складывать**: родитель и потомок могут одновременно попасть в топ.
- Символические ссылки не раскрываются. GNU du считает hard links один раз в пределах одного сканируемого корня.
- Для `/tmp` выводится только **общий размер**, без имён и рейтинга содержимого. Для подсчёта суммы `du --summarize` обходит метаданные, но не читает содержимое файлов.
- Сканирование рейтингов запускается только при открытии/обновлении отчёта, не по таймеру индикатора. Данные не сохраняются на диск.
- Потоковый обработчик держит только 20 крупнейших записей на текущий обход. В готовом отчёте сохраняется не более 20 записей на домашний каталог, а не полный список файлов.
- Недоступные и изменившиеся во время обхода файлы пропускаются без предупреждений и вывода stderr `du`, в том числе для `/tmp/systemd-private-*`. Размеры каталогов могут быть занижены. Полные сбои измерения и таймауты по-прежнему показываются. Плагин не использует sudo для измерений.
- Общий таймаут обхода всех домашних каталогов — 120 секунд; для `/tmp` — отдельные 120 секунд. При закрытии/обновлении окна или `/reload` дочерние процессы останавливаются.

`df` и `du` измеряют разное. Метаданные, удалённые, но ещё открытые файлы, снимки файловой системы и отсутствие доступа могут объяснять разницу между общим занятым местом и суммой доступных каталогов.

## Рекомендации по очистке

**Плагин не удаляет файлы и не запускает команды очистки.** Он показывает инструкции для ручного выполнения. Универсально безопасной команды удаления не существует: сначала проверьте назначение данных, необходимость резервной копии и отсутствие активных операций.

Команды проверки и ручной очистки показаны прямо в разделе `/tmp`, без необходимости нажимать `c`. На хосте предлагается системный механизм (в контейнере показываются отдельные ограничения, см. раздел Docker):

```bash
sudo systemd-tmpfiles --clean --prefix=/tmp
```

Он применяет настроенные возрастные ограничения и исключения, а не удаляет всё как `rm -rf /tmp/*`. При отсутствии подходящих правил может ничего не удалить. Это **не абсолютная гарантия**, что все оставшиеся нужными файлы будут сохранены.

Поддержка предварительного просмотра определяется через `systemd-tmpfiles --help`:

- Если есть `--dry-run`, сначала предлагается та же команда с `--dry-run`.
- Если нет, показывается `systemd-tmpfiles --cat-config --no-pager` для изучения правил. **Это не предпросмотр списка удаляемых файлов.** В частности, systemd 255 в текущей системе не поддерживает `--dry-run`.

Не добавляйте к рекомендации `--remove`/`--boot` и не заменяйте её массовым `rm`.

Для распознанных путей вашего домашнего каталога в топ-20 есть отдельные рекомендации:

| Каталог / назначение | Предлагаемый подход |
| --- | --- |
| `~/.npm` | `npm cache ls`, затем `npm cache verify` |
| `~/.cache/pip` | Проверка через `python3 -m pip cache info/list`, затем штатный `cache purge` |
| `~/.cache/uv` | `uv cache dir`, затем `uv cache prune` |
| pnpm store | `pnpm store path`, затем `pnpm store prune` с оговорками |
| Yarn Classic cache | Проверка версии; штатная очистка только для 1.x |
| Go build cache | `go env GOCACHE`, затем `go clean -cache` |
| Docker / Podman | Проверка daemon/context и объёмов; ограниченная штатная очистка кэша/образов с подтверждением, не volumes |
| Корзина | Просмотр через `gio trash --list`, затем подтверждение в файловом менеджере |
| Rust/toolchain, Gradle, Maven, node_modules, virtualenv | Без общей команды удаления; сначала определить проект и менеджер |
| Профили браузеров, IDE и `~/.config` | Штатный интерфейс приложения, не удаление профиля |
| journald | Оценка объёма и пример удаления старых архивных журналов с явным сроком хранения |
| APT на Debian/Ubuntu | Проверка скачанных `.deb`, затем `apt-get clean`, не `autoremove` |
| Неизвестные каталоги, базы, backups, volumes | **Никаких команд удаления**; определить владельца и пользоваться его инструментами |

Любая очистка кэшей может потребовать повторной загрузки данных и замедлить следующую сборку. Рекомендации поясняют ограничения, а не обещают безусловную безопасность. Распознавание расширяется через таблицу правил в `src/cleanup.ts`.

## Разработка и проверки

```bash
cd /home/poweruser/work/pi-disk-usage
npm install
npm test
npm run typecheck
LC_ALL=C npm test
LC_ALL=ru_RU.UTF-8 npm test
python3 scripts/smoke-tui.py
```

Peer-зависимости нужны для разработки и самостоятельных тестов; внутри pi используются библиотеки хоста. Не включайте их копии в runtime dependencies.

Тесты проверяют пороги процентов, учёт нескольких файловых систем, отсутствие двойного счёта, streaming top-20, нестандартные имена файлов, ссылки, /tmp-summary, ошибки доступа, отмену, таймауты, цвета, клик, размеры окна и правила рекомендаций. Smoke-тест запускает настоящий pi в PTY с русской и английской локалью в режимах `fullscreen` и `regular`, открывает `/disk`, проверяет рекомендации и закрытие. Никакие запросы модели или команды очистки не выполняются.

Отдельная проверка в одноразовом Docker-контейнере (без сети, без Docker socket и с read-only проектом):

```bash
docker run --rm --network none --read-only \
  --cap-drop ALL --cap-add SETUID --cap-add SETGID \
  --security-opt no-new-privileges \
  --tmpfs /home:rw,mode=755 --tmpfs /tmp:rw,mode=1777 \
  --mount type=bind,src="$PWD",dst=/work,readonly \
  -e PI_DISK_USAGE_CONTAINER_SMOKE=1 -e LC_ALL=C \
  node:22-bookworm-slim node /work/scripts/smoke-container.ts
```

Smoke-скрипт создаёт только тестовые каталоги внутри контейнера, затем сбрасывает права до UID/GID 65534. Проверяются занятый объём видимых файлов, отдельные топ-20 по домашним каталогам и молчаливый пропуск закрытого домашнего каталога. Для русского языка замените `LC_ALL=C` на `LC_ALL=ru_RU.UTF-8`.

Структура:

```text
src/index.ts     — регистрация, таймер и жизненный цикл
src/cache.ts     — общий приватный кэш и запуск worker под flock/timeout
src/cache-worker.ts — независимое измерение под блокировкой и атомарная запись
src/disk.ts      — df, потоковый du, сортировка, отмена
src/container.ts — определение контейнера, занятый объём и пороги GB
src/homes.ts     — доступные домашние каталоги и отдельный топ-20 для каждого
src/ui.ts        — индикатор, клик и окно отчёта
src/cleanup.ts   — рекомендации и проверка поддержки dry-run
src/i18n.ts      — определение локали и выбор перевода
test/            — автоматические тесты
scripts/         — smoke-тест настоящего TUI
```
